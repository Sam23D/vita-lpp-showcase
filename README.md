# Hello Vita — lpp-vita showcase

A homebrew app for the PlayStation Vita that demonstrates every function
[Lua Player Plus Vita](https://github.com/Rinnegatamante/lpp-vita) (lpp-vita)
exposes to Lua: 292 functions across 18 modules, organised as 23 demo screens.

No VitaSDK needed: the app is plain Lua, packaged with lpp-vita's prebuilt
interpreter (`eboot.bin`).

## Screens

| Area | Screens |
|------|---------|
| Graphics | Hello World, 2D primitives, images (PNG/JPG/BMP/GIF, sprites, render targets), fonts, rescaler, 3D render, ImGui |
| Input | buttons, sticks, front + rear touch, gyro, accelerometer |
| Media | sound (OGG/MP3/WAV/AIF/MIDI), microphone, video + subtitles, camera |
| System | OS dialogs + keyboard, timers, files, ZIP/PBP/SFO, SQLite, HTTP + FTP, sockets (echo server on :5000), system info |
| Unsafe build only | Registry, Danger Zone (reboot, app install, plugins — every action asks first) |
| Meta | Coverage: which API functions you have called this session |

## Install on a Vita

Requires a hacked Vita with VitaShell.

1. Download `lpp-showcase.vpk` (or build it, below).
2. Copy it to the memory card (USB mode or FTP in VitaShell; `make send VITA=<ip>` uploads to `ux0:/data/`).
3. In VitaShell select the file → X → Install package.
4. Launch "Hello Vita (lpp showcase)" from the home screen.

`lpp-showcase-unsafe.vpk` uses the unsafe interpreter (needed for Registry,
plugins, app install). Both share the title ID `LPPS00001`.

Optional flags (empty files in `ux0:/data/lpp-showcase/`):

- `jit_on` — enable the LuaJIT compiler (off by default because Vita3K can't run it)
- `autotest` — the app walks every screen by itself and saves screenshots to `shots/`

## Build

Requirements (Arch package names): `python`, `luajit`, `cairo`, `sqlite`, `zip`.
Regenerating assets also needs `ffmpeg`, `imagemagick` and `ttf-liberation`.

```sh
make            # mock tests (safe + unsafe) and both VPKs in dist/
make vpk        # dist/lpp-showcase.vpk
make vpk-unsafe # dist/lpp-showcase-unsafe.vpk
make test       # headless run of the whole app against the PC mock
make assets     # regenerate app/assets (all generated locally)
make api        # regenerate tools/mock/lpp_api.lua from an lpp-vita checkout (LPP_SRC=path)
```

`tools/build.py` downloads the lpp-vita Nightly interpreter once into `.cache/`
and checks it against a pinned SHA-256.

## Testing

**On the PC (`make test`)** — `tools/mock/` is a LuaJIT + cairo stand-in for
lpp-vita. Its function signatures are generated from lpp-vita's C source
(`tools/gen_api.py`), so argument counts, types and unsafe-only checks match
the real interpreter. The driver opens every screen, runs every action, saves
screenshots to `build/shots/` and fails on crashes, unexpected errors or
uncalled functions. Camera, audio and network are simulated.

**In Vita3K (`tools/emu.sh`)** — installs the VPK into Vita3K's filesystem and
boots it (`--unsafe`, `--autotest`). Needs the Vita3K AppImage in
`~/.local/opt/vita3k/` and the official PS Vita firmware installed in it.

Known emulator issue: the Fonts screen can crash Vita3K (seems to be the
emulator's font handling; not yet confirmed on hardware).

## lpp-vita quirks this app works around

- `Graphics.loadImage(path, MEM_RAM)` always errors — use the one-argument form.
- MP3 must start with an ID3v2.3 tag; FLAC isn't supported.
- `drawLine` / `fillRect` / `fillEmptyRect` take `(x1, x2, y1, y2)`.
- `Timer.setTime` on a running timer gives wrong values — pause first.
- `createImage` only uses the red byte of the fill colour.
- Only one async task at a time.
- `Socket.connect` to an unresolvable host crashes the interpreter — check Wi-Fi first.
- One glyph atlas per font handle: use a handle per pixel size instead of calling `setPixelSizes` repeatedly.

## Layout

```
app/            everything that goes into the VPK (index.lua, lib/, scenes/, assets/, sce_sys/)
tools/          build.py (VPK), sfo.py (PARAM.SFO), make_assets.py, gen_api.py, emu.sh, repro.sh
tools/mock/     PC mock of lpp-vita + headless test driver
```
